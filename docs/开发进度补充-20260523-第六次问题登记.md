# 2026-05-23 第六次问题登记

## 1. 本轮新增用户反馈

本轮新增的待处理问题有四类：

1. **AI 历史与界面状态存储不稳**
   - AI 处于长时间思考时，用户点击历史再返回原会话，生成可能中断或看不到最终回复。

2. **慢回复缺少超时与自动换模型**
   - 需要为单模型设置最长 3 分钟等待时间；
   - 超时后自动切换备用模型 / Provider，而不是一直停在“思考中”。

3. **部分页面缺少返回入口**
   - 需要继续全量检查所有页面、弹层、细节页、地图全屏页是否都有明确返回选项。

4. **定位文案与真实位置不一致**
   - 地图图片已经显示真实位置；
   - 但配套文案仍显示“设备定位...”，语义不准确。

## 2. 已核对到的当前代码事实

### 2.1 生成中的回复目前仍主要依赖内存态

已核对：

- `app/src/main/java/me/rerere/rikkahub/service/ChatService.kt`
  - 流式生成过程中会持续 `updateConversation()`；
  - 但 `updateConversation()` 只更新当前 `ConversationSession` 的内存状态；
  - `saveConversation()` 仍主要在生成完成后统一落库。

- `app/src/main/java/me/rerere/rikkahub/service/ConversationSession.kt`
  - 生成中的会话会因为 `isGenerating` 保持 session 存活；
  - 这属于“内存保活”，不是“生成态持久化恢复”。

- `Zhitu.html`
  - `conversation.isGenerating`
  - `historyConversations`
  - `profileUiState`
  - 这些页面状态主要依赖宿主实时注入 `hostState`。

结论：

- 当前实现可以在同一轮会话内继续展示生成中的内容；
- 但当用户切历史、切页面、WebView 重建或应用异常中断时，未完成回复没有稳定恢复机制。

### 2.2 当前没有正式的“3 分钟超时 + 自动换模型”机制

已核对：

- `ai/src/main/java/me/rerere/ai/util/SSE.kt`
  - 建立 `event-stream` 后会主动执行 `call?.timeout()?.cancel()`；
  - `onRetryChange()` 当前直接忽略，没有自动重试。

- `docs/开发文档.md`
  - 之前只记录了 Provider fallback 仍需继续回归；
  - 还没有把“单模型最长等待 3 分钟、超时后自动切换”落成正式策略。

结论：

- 当前如果某个模型慢响应但不报错，界面可能长时间停在思考中；
- 这和用户反馈的“AI 回复慢时应该设置超时并更换模型”一致。

### 2.3 定位文案目前是固定写死的

已核对：

- `app/src/main/java/me/rerere/rikkahub/ui/pages/chat/ChatMapDrawer.kt`
  - `DEVICE_LOCATION_LABEL = "设备定位"`
  - `buildLocationPoint()` 中也直接 `append("设备定位")`
  - 但同段逻辑已经能拿到 `poiName` 和 `address`

结论：

- 当前不是定位失败；
- 而是已经有真实地点语义时，说明文案仍使用了过于泛化的固定文本。

### 2.4 页面返回入口还没有形成全量 QA 清单

已核对：

- 现有文档已经覆盖历史、收藏、地图、设置等主流程入口；
- 但还没有一份“逐页检查是否有返回按钮 / 返回目标是否正确”的完整验收表。

结论：

- “有些页面没有返回选项”目前更像一类尚未做完的导航覆盖问题；
- 需要单独做一次全页面导航回归，而不是零散补。

## 3. 建议修复顺序

### P0：先补生成态持久化与恢复

- 生成中的 assistant 草稿节流落库
- `isGenerating` 与关键界面状态可恢复
- 从历史会话返回后能续显、重试或明确提示已中断

### P1：再补 3 分钟超时与自动换模型

- 单模型最长等待 180000ms
- 超时后 cancel 当前请求
- 自动切换候选 provider / model
- 在 UI 上明确提示切换动作

### P2：做一轮页面返回入口总回归

- 所有页面
- 所有弹层
- 所有地图全屏 / 推荐详情 / 设置二级页

### P3：修正文案一致性

- 真实位置已可得时优先显示“当前位置”或真实地点名
- 仅在没有地点语义时回退“设备定位”
