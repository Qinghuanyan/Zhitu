# Zhitu TravelHub 开发进度补充（2026-05-21 第三次同步）

## 1. 本轮真实排障结论

本轮不是只看代码，而是基于 `emulator-5554` 做了实际联调。

定位出的两个核心问题：

1. **HTML 运行时脚本被误禁用**
   - `ai_travel_planner.html` 里最后一段真正负责 `__ZHITU_RECEIVE_STATE__` / `renderApp()` 的脚本，
     被错误改成了 `type="application/x-zhitu-disabled"`。
   - 直接结果：
     - 页面只显示静态头部；
     - 中间主体空白；
     - 发送、tab、地图摘要等全部失效。

2. **Travel Planner Assistant 上游额度耗尽**
   - 模拟器日志确认上游返回：
     - `429 MONTHLY_LIMIT_EXCEEDED`
   - 直接结果：
     - 用户消息能进入会话；
     - 但原本依赖模型抽取 `TravelPlanningBrief` 的流程会失败；
     - 不加兜底时，无法从用户输入直接生成 itinerary。

## 2. 本轮已完成修复

- 恢复最后一段 TravelHub 运行时脚本为可执行状态；
- 保留前 3 段旧 demo script 为禁用状态，避免旧示例逻辑重新接管；
- 为 `tailwind` / `lucide` 加入更安全的运行保护；
- 在 `ChatService.generateTravelBrief()` 中加入 **本地兜底 brief 解析**：
  - 从用户输入提取目的地、天数、人数、预算、偏好、交通偏好；
  - 当上游模型 429 / 不可用时，仍能生成 `TravelPlanningBrief`；
- 复用现有 `enrichGeneratedTravelPlan(...)` fallback 逻辑，
  在 brief 可用时继续产出：
  - `itineraryDays`
  - `hotels`
  - `foods`
  - `pois`
- 去掉 HTML 页面上的运行时调试浮层，避免最终界面出现 `[info] render ok ...`。
